## Zweck

Ein GPS-Tracker soll im zweiten Teamauto mitfahren. Bisher kannte der Server
nur eine Sorte Gerät: alles, was über `POST /positions` meldet, ist ein Fahrer
im Rennen. Ein Wagen mit derselben Behandlung hätte fünf Nebenwirkungen, von
denen eine ernst ist:

| | Wirkung vor 2.6.0 |
|---|---|
| **1** | **Der Wagen zählt Runden.** `pruefeRundendurchgang()` lief für jeden Tracker im aktiven Rennen. Ein Auto, das zum Start zurückfährt oder abkürzt, hebt den Rundenzähler des ganzen Rennens. |
| 2 | Er wurde Kandidat für die Gruppenbildung und konnte in eine Fahrergruppe geraten. |
| 3 | Er stand in der Displayliste, obwohl er kein Display hat. |
| 4 | Er trug den normalen Pin, war also vom Feld nicht zu unterscheiden. |
| 5 | Sein Schnitt wurde ausgewiesen, als führe er das Rennen mit. |

Zweitens ließ sich ein Tracker bisher nur zuordnen, wenn er bereits auf der
Karte stand: das Zuordnungsmenü hängt am Marker. Wer am Vorabend vorbereiten
wollte, konnte es nicht — obwohl der Server die Zuordnung längst ohne
Lebenszeichen annimmt.

## Was neu ist

**Ein Tracker hat jetzt einen Typ.** Sportler (Vorgabe, entspricht dem
Verhalten bis 2.5.2) oder Teamauto. Ein Teamauto

- zählt **keine Runden**,
- ist **kein Kandidat** für die Gruppenbildung,
- steht **nicht** in der Displayliste,
- trägt ein **Quadrat** in der Rennfarbe statt des Tropfens,
- **behält** seine Streckenposition — man sieht weiter, bei welchem
  Kilometer der Wagen steht.

Der Typ gehört zum Gerät, nicht zum Rennen: er überlebt das Rennende. Die
Rennzuordnung wird beim Beenden weiterhin gelöst (`loeseTrackerZuordnung()`,
unverändert seit 1.16.0).

**Zuordnen geht jetzt vor dem ersten Lebenszeichen.** In der Kopfzeile jeder
Veranstaltung steht ein Knopf 📡. Er klappt eine Liste aller dem Server
bekannten Tracker auf — auch der offline stehenden. Je Zeile: Rennen
(Aufklappmenü mit den Rennen **dieser** Veranstaltung) und Typ (Schalter
🚴/🚗). Ein Gerät, das der Server noch nie gesehen hat, lässt sich unten über
seine ID aufnehmen.

Das bestehende Marker-Menü auf der Karte bleibt und bekommt denselben
Typ-Schalter über der Rennauswahl.

## Bedienung

| Weg | wofür |
|---|---|
| 🏁 Rennen → 📡 in der Kopfzeile der Veranstaltung | Vorbereitung am Laptop, auch ohne laufende Geräte |
| Rechtsklick / langer Druck auf den Marker | Korrektur im Rennen, wenn der Wagen schon auf der Karte steht |

Beide Wege schreiben denselben Serverzustand. Welches Rennen man auf der
Website **ansieht**, bleibt davon unberührt — das ist weiterhin reiner
Gerätezustand (`lt.meinRennen`, `localStorage`) und wandert nie in eine
Zuordnung.

## Schnitt

**Server (`server.js`, +100 / −3)**

- `trackerRolle{}` neben `trackerRace{}`. Einziger Wert `'teamauto'`; kein
  Eintrag heißt Sportler. Absichtlich **nicht** `trackerAuto` genannt —
  `autoDisplay{}` steht im selben Modul und meint „automatischer Anzeigetext".
- Persistenz im vorhandenen `runtime`-Setting als Liste `teamautos`, analog zu
  `autoDisplay`. Keine neue Tabelle, keine neue Spalte.
- `istTeamauto(id)` und `autosOfRace(raceId)`.
- `verfolgeStrecke()`: `if (istAktiv(rid) && !istTeamauto(id))` statt
  `if (istAktiv(rid))`. Die Rundenlogik selbst ist unverändert — sie wird nur
  nicht mehr betreten. Der `else`-Zweig pflegt `trackerS[id]` weiter, deshalb
  bleibt die Streckenposition erhalten.
- `GET /positions` liefert `role: 'teamauto'` **nur** für Teamautos. Für einen
  Stand ohne Rollen ist die Antwort byte-gleich zu 2.5.2.
- `POST /tracker-role` (SpoLei), `GET /trackers` (SpoLei).
- `raceView()` um `trackerAutos` erweitert.

**Karte (`map/map.js`, +93 / −10)**

- `autoPin(farbe)`: 30×30-Quadrat, Rennfarbe als Fläche, Wagen nur als weißer
  Umriss. Ankerpunkt in der Mitte statt unten — ein Quadrat hat keine Spitze.
  Die Fläche ist rund doppelt so groß wie beim Pin, damit die Rennfarbe auch
  bei Sonne und flachem Blickwinkel erkennbar bleibt.
- `trackerIcon(farbe, rolle)` als einziger Ort der Symbolwahl.
- `markerRolle{}` als zweiter Merker neben `markerRace{}`; `setzeRennFarbe()`
  bekommt einen dritten Parameter. Ohne den zweiten Merker hätte ein
  Rollenwechsel bei gleicher Rennfarbe das Symbol nicht getauscht.
- Typ-Schalter im Marker-Menü.
- `gruppenKandidaten` an beiden Stellen um `!istAuto` erweitert.

**Rennverwaltung (`race/events.js` +33, `race/events-ui.js` +115 / −6)**

- Datenschicht: `trackerList`, `loadTrackers()`, `setTrackerRace()`,
  `setTrackerRole()`, `addTrackerId()`.
- `addTrackerId()` benutzt den vorhandenen `POST /rename-tracker` — eine
  eigene Route dafür wäre doppelt gewesen.
- `trackerPanelHtml(ev)` plus Zustand `trackerEvId`, Knopf 📡, ein
  `change`-Listener für die Aufklappmenüs (ein `<select>` meldet sich nicht
  mit `click`).
- Die Trackerzeile unter dem Rennen weist die Autos getrennt aus:
  „2 Tracker: … · davon 1 Auto".
- Ist ein Tracker einem Rennen **einer anderen Veranstaltung** zugeordnet,
  steht dieses als eigener Eintrag im Aufklappmenü und geht beim Rendern nicht
  still verloren.

**Displays (`race/displays.js`, +6 / −1)** — Teamautos fallen aus der Liste.

**CSS (`css/app.css`, +72)** — `.tk-*` für das Panel, `.typWahl` für den
Schalter im Marker-Menü. Der Selektor `.markerMenu .typWahl button` ist eine
Klasse spezifischer als `.markerMenu button` und gewinnt damit unabhängig von
der Reihenfolge im Stylesheet.

## Was ausdrücklich nicht passiert

- **`POST /betreuer-position` und `POST /team-position` sind unberührt.** Der
  Web-Schalter „Teamauto" und „📍 Standort teilen" verhalten sich wie in 2.5.2.
  Der zweite Wagen läuft über die native App, also über `POST /positions` —
  dort greift die Rolle.
- **Die Rückfallebene bleibt.** Ein Tracker ohne Zuordnung gilt weiterhin für
  das Leitrennen (`raceOfTracker()`). Der Umbau dieser Stelle war als
  Baustein C besprochen und ist bewusst nicht Teil dieser Lieferung.
- **`pruefeRundendurchgang()` und `startOffset` sind inhaltlich unverändert.**
  Der einzige Eingriff ist die Bedingung davor.
- **`race/favorites.js` ist nicht angefasst.**

// Rolle eines Trackers setzen: 'teamauto' oder null (= Sportler).
// Eigener Endpoint statt eines Zusatzfeldes an /tracker-race: so
// bleibt die Zuordnung unberuehrt, und ein Rollback trifft genau eine

app.post('/tracker-role', requireSpolei, (req, res) => {
  const { trackerId, role } = req.body || {};
  if (!trackerId) return res.status(400).json({ error: 'trackerId required' });
  const key = String(trackerId).slice(0, 40);

  if (role === 'teamauto') {
    trackerRolle[key] = 'teamauto';
    persistRuntime();
    console.log(`\u{1F697} Tracker ${key} ist ein Teamauto`);
    return res.json({ ok: true, role: 'teamauto' });
  }

  if (role === null || role === undefined || role === '' || role === 'sportler') {
    delete trackerRolle[key];
    persistRuntime();
    console.log(`\u{1F6B4} Tracker ${key} ist ein Sportler`);
    return res.json({ ok: true, role: null });
  }

  res.status(400).json({ error: 'role muss "teamauto", "sportler" oder null sein' });
});

// Alle bekannten Tracker - fuer die Trackerverwaltung im Rennen-Tab.
// Bewusst aus vier Quellen zusammengesetzt, damit auch ein Geraet
// auftaucht, das gerade nichts sendet: nur so laesst sich am Vorabend
// zuordnen. Betreuer-Marker und das Teamauto des Handys bleiben
// aussen vor - beide sind keine Tracker im Sinne dieser Liste.
app.get('/trackers', requireSpolei, (req, res) => {
  const ids = new Set();
  for (const id of Object.keys(positions))           ids.add(id);
  for (const id of Object.keys(pending))             ids.add(id);
  for (const id of Object.keys(trackerDisplayNames)) ids.add(id);
  for (const id of Object.keys(trackerRace))         ids.add(id);
  for (const id of Object.keys(trackerRolle))        ids.add(id);
  ids.delete('TEAMAUTO');

  const now = Date.now();
  const out = [];
  for (const id of ids) {
    if (String(id).startsWith('betreuer-')) continue;
    const pos = positions[id];
    const pnd = pending[id];
    const ts  = Math.max((pos && pos.timestamp) || 0, (pnd && pnd.timestamp) || 0) || null;
    const rid = trackerRace[id] && races[trackerRace[id]] ? trackerRace[id] : null;
    out.push({
      id,
      displayName: trackerDisplayNames[id] || id,
      raceId:      rid,
      raceName:    rid ? races[rid].name : null,
      role:        istTeamauto(id) ? 'teamauto' : null,
      timestamp:   ts,
      online:      ts !== null && now - ts < 60000
    });
  }
  out.sort((a, b) => a.displayName.localeCompare(b.displayName));
  res.json({ trackers: out });
});
