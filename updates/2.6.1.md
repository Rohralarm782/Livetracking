## Zweck

Bei drei gleichzeitig sichtbaren Rennen auf derselben Straße waren nur zwei
Linien zu sehen. Die dritte lag exakt unter einer anderen.

Der Versatz in 2.6.0 hatte zwei Löcher:

| | Verhalten bis 2.6.0 |
|---|---|
| **1** | **Die Stufe hing am Startpunkt.** Zwei Strecken galten nur dann als deckungsgleich, wenn ihr erster GPX-Punkt auf vier Nachkommastellen (~11 m) übereinstimmte. Drei Rennen aus verschiedenen GPX-Quellen bekamen alle Stufe 0 und lagen übereinander. Rennen, die nur ein Teilstück teilen, waren nie erfasst. |
| **2** | **Die Richtung war fest diagonal.** `translate(+3px, +3px)` schiebt nach rechts unten. Eine Straße, die selbst von links oben nach rechts unten verläuft, verschiebt sich damit *entlang ihrer selbst* — sichtbarer Abstand null, unabhängig von der Stufe. |

Nicht ursächlich war die Farbvergabe: `sichereFarbe()` vergibt aus einer
festen Achterpalette nur unbelegte Farben. Die dritte Linie wurde gezeichnet,
sie lag nur darunter.

## Was neu ist

**Die Strecken laufen wie Fahrspuren nebeneinander.** Jede Linie wird
senkrecht zu ihrer *eigenen* Fahrtrichtung versetzt, segmentweise. Damit
funktioniert die Trennung in jeder Himmelsrichtung, auch auf der Diagonale.

- **Abstand 5 px, in jedem Zoom gleich.** Gerechnet wird im Pixelraum der
  Karte; beim Zoomwechsel werden die Punkte neu gebildet (`zoomend`).
- **Das eigene Rennen liegt auf der Fahrbahn** (Versatz 0), wird **zuletzt**
  gezeichnet und ist **eine Spur stärker** (weight 5 statt 4). Es kann damit
  nie verdeckt sein — und die Strecke, auf die es ankommt, liegt exakt dort,
  wo die Straße ist.
- **Weiße Kontur** unter jeder Linie, sobald mehr als eine Strecke auf der
  Karte liegt. Bei genau einer Strecke entfällt sie: das Bild ist dann
  identisch zu 2.6.0.
- Die Stufe hängt jetzt an der Reihenfolge der Rennliste, nicht mehr am
  Startpunkt. Vier gleichzeitige Rennen bekommen 0 / +5 / −5 / +10 px.

## Umsetzung ohne Plugin

Besprochen war Variante A mit `leaflet-polylineoffset`. Beim Lesen des Plugins
habe ich mich **dagegen** entschieden und es selbst gerechnet — 40 Zeilen in
`map/gpx.js`. Grund: das Plugin überschreibt `L.Polyline.prototype._projectLatlngs`
**global**. Das ist die Projektionsfunktion *jeder* Polylinie der App —
Fahrerspuren, Verpflegungszonen, Track-Segmente. Ein Fehler dort träfe die
ganze Karte, nicht nur die Streckenlinien. Dafür ist die Ersparnis zu klein.

Die Optik ist dieselbe wie im Mockup, der Eingriff bleibt auf eine Funktion
begrenzt, und es kommt kein `<script>`-Tag und keine CDN-Abhängigkeit hinzu.
Wenn du das anders siehst, ist der Umbau auf das Plugin jederzeit möglich —
`versetzteCoords()` wäre dann die einzige Stelle, die wegfällt.

## Was ausdrücklich nicht passiert

- **Im Streckenmodus gibt es keinen Versatz.** Harte Regel im Code:
  `gpxVersatz = (streckenModus && zielRaceId) ? {} : versatzPlan(zeichnen)`.
  Der Kartentipp meldet die Koordinate unter dem Finger; läge die Linie
  daneben, wanderte der Zielstrich mit — bei Zoom 14 sind 5 px rund 30 m, und
  daran hängt die Rundenzählung. Diese Zeile ist der empfindlichste Punkt der
  Lieferung.
- **`gpxByRace` und `gpxCoords` bleiben unberührt.** Der Versatz existiert nur
  in den gezeichneten Punkten. Kilometrierung, `gpxPointAt`, `gpxSlice`,
  Marker- und Zielflaggenlage rechnen weiter mit der echten Strecke.
- **`startOffset` und `pruefeRundendurchgang` sind nicht angefasst.**
  `server.js` ist byte-identisch.
- **Zonen bleiben wie besprochen unverändert** (Verpflegung, freie Punkte).
  Sie liegen weiter auf der Fahrbahn; die zugehörige Streckenlinie kann bis zu
  10 px danebenliegen. Ebenso die Zielflaggen und Wertungssymbole — sie stehen
  auf der Straße, nicht auf der Spur.
- **`race/favorites.js` ist nicht angefasst.**

// Abstand zweier Spuren in Bildschirmpixeln. Kleinster Wert, bei dem
// zwei Linien der Staerke 4 samt weisser Kontur noch getrennt lesbar
// sind - und klein genug, dass die Strecke im Uebersichtszoom nicht
// erkennbar neben der Strasse liegt.
const VERSATZ_PX = 5;

// Wer faehrt auf welcher Spur. Das eigene Rennen bekommt immer die
// Null und liegt damit exakt auf der Fahrbahn, so wie eine einzelne
// Strecke bis 2.6.0; die uebrigen wandern abwechselnd nach rechts und
// links. Die Stufe haengt an der Reihenfolge der Rennliste, nicht mehr
// am Startpunkt der Strecke - genau daran scheiterte 2.6.0, sobald
// zwei Rennen nur ein Teilstueck gemeinsam hatten.
function versatzPlan(ids) {
  const stufen = [0, 1, -1, 2];   // MAX_AKTIVE_RENNEN = 4
  const mein   = (typeof meinRaceId === 'function') ? meinRaceId() : null;
  const folge  = (ids.indexOf(mein) !== -1)
    ? [mein].concat(ids.filter(id => id !== mein))
    : ids.slice();
  const plan = Object.create(null);
  folge.forEach((id, i) => {
    plan[id] = (stufen[i] === undefined ? 0 : stufen[i]) * VERSATZ_PX;
  });

// Punkte einer Strecke um px Bildschirmpixel senkrecht zur
// Fahrtrichtung verschieben. Gerechnet wird im Pixelraum der Karte und
// danach zurueck nach Grad; deshalb muss das Ergebnis bei jedem
// Zoomwechsel neu gebildet werden (siehe aktualisiereVersatz).
//
// An einer Ecke zaehlt die Winkelhalbierende beider angrenzenden
// Segmente, verlaengert um 1/cos - sonst schnuerte die Linie in der
// Kurve ein. Bei einer Kehre liefe der Faktor gegen unendlich, deshalb
// ist er bei 0.55 gedeckelt: die Spitze wird dort leicht abgeflacht
// statt quer ueber die Karte zu schiessen.
//
// gpxByRace bleibt unberuehrt. Der Versatz existiert nur in den
// gezeichneten Punkten - Kilometrierung, Marker und Zielstrich rechnen
// weiter mit der echten Strecke.
function versetzteCoords(coords, px) {
  const c = coords || [];
  if (!px || c.length < 2) return c;
  const p = c.map(q => map.latLngToLayerPoint(L.latLng(q[0], q[1])));
  const n = p.length;
  const norm = [];
  for (let i = 0; i < n - 1; i++) {
    const dx = p[i + 1].x - p[i].x, dy = p[i + 1].y - p[i].y;
    const len = Math.sqrt(dx * dx + dy * dy) || 1;
    norm.push([-dy / len, dx / len]);
  }
  const out = [];
  for (let i = 0; i < n; i++) {
    const a = norm[i === 0 ? 0 : i - 1];
    const b = norm[i === n - 1 ? n - 2 : i];
    let nx = a[0] + b[0], ny = a[1] + b[1];
    const len = Math.sqrt(nx * nx + ny * ny) || 1;
    nx /= len; ny /= len;
    const cos = Math.max(0.55, a[0] * nx + a[1] * ny);
    const ll = map.layerPointToLatLng(
      L.point(p[i].x + nx * px / cos, p[i].y + ny * px / cos));
    out.push([ll.lat, ll.lng]);
  }
  return out;
}

// Beim Zoomen aendert sich das Verhaeltnis von Grad zu Pixel. Ohne
// Nachrechnen laegen die Spuren in der Uebersicht meterweit
// auseinander und im Nahzoom wieder deckungsgleich. Angefasst wird nur
// die Geometrie der Linien - Marker, Zielflaggen und Zonen bleiben
// stehen, deshalb kein volles zeichneStrecken().
function aktualisiereVersatz() {
  for (const id of Object.keys(gpxLayerByRace)) {
    const px = gpxVersatz[id] || 0;
    if (!px) continue;
    const neu = versetzteCoords(gpxByRace[id], px);
    try {
      gpxLayerByRace[id].setLatLngs(neu);
      if (gpxKontur[id]) gpxKontur[id].setLatLngs(neu);
    } catch (e) { /* Layer schon weg */ }
  }
}
