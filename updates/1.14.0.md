# Livetracking 1.14.0 — Streckenpunkte: Wertung, Berg, Verpflegungszone

Stand vom 24.08.2026, aufgesetzt auf den Repo-Stand
`codeload.github.com/Rohralarm782/Livetracking/zip/refs/heads/main`,
HEAD `60f7218`, abgerufen 20:34 UTC. Vorgängerstand 1.13.0, unverändert
übernommen.

Gebaut nach den sechs Entscheidungen D1–D6, alle wie vorgeschlagen bestätigt.
Keine Datenmigration, keine neue Umgebungsvariable, keine Schemaänderung.

## Zweck

Bis 1.13.0 gab es genau einen Punkt auf der Strecke: den Zielstrich. Jetzt
lassen sich alle weiteren Punkte eintragen, die im Rennen zählen — Wertung,
Bergwertung, Verpflegungszone, ein separater Startpunkt für den neutralisierten
Anfahrtsweg, und ein freier Punkt für alles andere.

## Die sechs Entscheidungen, wie umgesetzt

**D1 — `startOffset` bleibt, wo es ist.** Die Marker kommen additiv daneben.
Am Start/Ziel-Versatz hängt der Rundenzähler mit Mitte-Bedingung, Zeitsperre
und Rückwärtserkennung; `pruefeRundendurchgang()` ist **nicht angefasst**.
Der Zielstrich ist damit weiterhin kein Marker, sondern was er war.

**D2 — Verpflegung und freie Punkte dürfen eine Ausdehnung haben.** Feld
`sEnde`. Auf der Karte werden sie als eingefärbter Streckenabschnitt gezeichnet,
nicht als Punkt. Wertung, Berg und Start bleiben Punkte — setzt jemand dort ein
`sEnde`, verwirft der Server es still (geprüft).

**D3 — Beliebig viele Punkte je Typ,** gedeckelt auf 20 je Rennen. Der Deckel
existiert, weil `/active` von jedem Gerät alle 20 Sekunden geholt wird.

**D4 — Rundenbezug.** Feld `runden`: leer heißt jede Runde, sonst z. B. „2, 4".
Eingabe als freier Text, der Server normalisiert (dedupliziert, sortiert,
begrenzt auf 1–99). Die Anzeige „nächster Punkt" überspringt Punkte, die in der
laufenden Runde nicht gelten.

**D5 — „nächste Wertung in 1,2 km" in der Rennuhr.** Bezugspunkt ist die Spitze.
Damit dafür überhaupt eine Streckenposition zur Verfügung steht, liefert
`GET /positions` jetzt `s` je Tracker mit — der Server rechnet den Wert ohnehin
bei jedem Punkt, bisher kam er nur aus dem Verlauf und damit nur bei
eingeschaltetem Zeitabgleich.

Der Sonderfall am Zielstrich ist mitbehandelt: hat die Spitze gerade überquert
(relativ ≈ 0) und das Gruppetto noch nicht (relativ ≈ L), wäre der Hinterste
rechnerisch der „Weiteste". Liegen Tracker auf beiden Seiten der Linie, zählen
deshalb nur die, die schon durch sind.

**D6 — nichts davon geht auf den Garmin.** Der Anzeigetext bleibt unverändert,
`buildAutoText()` ist nicht angefasst, keine neue Berechtigung, keine neue
Store-Prüfung.

## Bedienung

Aus dem Panel „📐 Start/Ziel" wird **„📐 Strecke"**. Oben unverändert der
Zielstrich, darunter neu „Punkte auf der Strecke":

- **✚ Punkt** öffnet das Formular. Erst die Art wählen (🏅 Wertung · ⛰ Berg ·
  🍌 Verpflegung · 🚩 Start · 📌 Frei), dann Name, Kilometer und optional die
  Runden. Bei Verpflegung und Frei erscheint zusätzlich ein Feld für das Ende;
  bleibt es leer, ist der Punkt ein Punkt.
- **📍** legt ihn auf die aktuelle Position.
- **🗺 Auf Karte tippen** erscheint erst, wenn der Punkt schon existiert, und
  nur beim aktiven Rennen.
- **✎ / ✕** je Zeile zum Ändern und Entfernen.

Auf der Karte tragen die Punkte ein Symbol im weißen Kreis, Zonen zusätzlich
einen eingefärbten Streckenabschnitt. Der Tooltip nennt Name, Kilometer und
gegebenenfalls die Runden.

## Sicherheit gegen ein verschobenes Ziel

Das war das Hauptrisiko dieses Updates: Ein versehentlich verschobener
Zielstrich verwirft mitten im Rennen die Rundenzählung. Drei unabhängige Riegel:

1. **Getrennte Funktionen.** `onTrackClick()` ruft entweder `sendeZiel()` oder
   `sendeMarkerPunkt()`. Es gibt keinen Schalter innerhalb einer Funktion und
   damit keinen Weg, auf dem ein Markertipp am Zielstrich landet.
2. **Die Kartenleiste sagt immer, was der nächste Tipp setzt** — Titel mit
   Symbol und Name des Punkts, dazu ein violetter Rand statt des blauen.
3. **Das km-Feld der Leiste gehört dem Zielstrich** und wird in der Markerlage
   ausgeblendet; `streckenKmUebernehmen()` in `core/ui.js` bricht zusätzlich ab,
   wenn ein Marker ausgewählt ist.

## Breaking Changes

Keine.

- `raceMeta` bekommt ein Feld `marker`. Alte Stände aus der Datenbank kennen es
  nicht; `raceMetaOf()` rüstet es beim ersten Zugriff nach.
- `raceView()` und `/active` liefern ein zusätzliches `marker[]`, `/positions`
  ein zusätzliches `s`. Ältere Clients ignorieren beides.
- `setStreckenModus()` bekommt einen dritten Parameter. Alle bestehenden Aufrufe
  mit zwei Argumenten verhalten sich unverändert.

**Eine Verhaltensänderung, die zu kennen ist:** Wird die Strecke eines Rennens
gelöscht, werden seine Marker mitgelöscht. Sie sind Meter auf genau dieser
Strecke und würden bei der nächsten an falscher Stelle wieder auftauchen. Der
Start/Ziel-Versatz bleibt dagegen stehen — daran hängt der Rundenzähler.
Wird eine Strecke **ersetzt**, bleiben die Marker unangetastet; nach einem
Streckenwechsel gehören die Kilometer also geprüft.

## Rollback

Vollständig durch Zurücklegen der acht Dateien. Ein zurückgerollter Stand liest
`raceMeta` wie bisher und ignoriert das Feld `marker` — es bleibt in der
Datenbank stehen und ist nach einem erneuten Deploy wieder da. Es gibt keinen
Zustand, den der alte Stand nicht verarbeiten kann.

  return 'm' + Date.now().toString(36) + Math.random().toString(36).slice(2, 4);

// Meter auf die Runde falten - dieselbe Rechnung wie bei startOffset.
function faltenAufRunde(raceId, v) {
  const g = trackGeometry(raceId);
  const x = Number(v) || 0;
  return g ? ((x % g.L) + g.L) % g.L : Math.max(0, x);
}

// "2,4,6" bzw. [2,4,6] -> [2,4,6]. Leer heisst: gilt in jeder Runde.
function normalizeRunden(v) {
  const roh = Array.isArray(v) ? v : String(v === undefined || v === null ? '' : v).split(',');
  const s = new Set();
  for (const x of roh) {
    const n = parseInt(x, 10);
    if (n >= 1 && n <= 99) s.add(n);
  }
  return [...s].sort((a, b) => a - b);
}

  const b = req.body || {};

  const typ = String(b.typ || '').toLowerCase();
  if (!MARKER_TYPEN.includes(typ)) {
    return res.status(400).json({ error: 'typ muss sein: ' + MARKER_TYPEN.join(', ') });
  }

  // derselben Rechnung projiziert wie eine GPS-Meldung.
  let s;

    const p = projectToTrack(r.id, b.atLat, b.atLon);
    if (p === null) return res.status(400).json({ error: 'Keine Strecke hinterlegt' });
    s = p;
  } else if (b.s !== undefined && b.s !== null && b.s !== '') {
    s = faltenAufRunde(r.id, b.s);

// Laeuft ueber den Streckenanfang hinweg, wenn s2 kleiner ist als s1 -
// eine Verpflegungszone kann den Zielstrich einschliessen.
function gpxSlice(s1, s2) {
  if (gpxCoords.length < 2) return [];
  const cum = gpxCumulative();
  const L   = cum[cum.length - 1];
  if (!L) return [];
  const a = ((s1 % L) + L) % L;
  let laenge = (((s2 - s1) % L) + L) % L;
  if (laenge < 1) laenge = 1;          // entartete Zone bleibt sichtbar
  const zwischen = [];
  for (let i = 0; i < gpxCoords.length; i++) {
    const d = (((cum[i] - a) % L) + L) % L;
    if (d > 0 && d < laenge) zwischen.push({ d, p: gpxCoords[i] });
  }
  zwischen.sort((x, y) => x.d - y.d);
  return [gpxPointAt(a), ...zwischen.map(z => z.p), gpxPointAt(a + laenge)]
    .filter(Boolean);
}

  if (roh === '') return null;
  const v = parseFloat(roh.replace(',', '.'));

}
