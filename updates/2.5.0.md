# Livetracking 2.5.0 — Rechte: Betreuer führt Taktik, Rennen bleibt SpoLei

**Datum:** 01.09.2026
**Typ:** Feature (Server + Frontend) — Rechtevergabe
**Basis:** v2.4.1 („Startausschnitt: Strecke statt Berlin")
**Repo-Stand:** `codeload.github.com/Rohralarm782/Livetracking/zip/refs/heads/main`,
abgerufen **01.09.2026, 19:05 UTC**

Sieben geänderte Dateien plus dieses Protokoll. **+72 / −15 Zeilen.**
Keine neue Route, keine Schemaänderung, keine neue Umgebungsvariable.
`race/favorites.js` unberührt.

---

## Zweck

Mit jeder neuen Funktion wird ein Fehlgriff im Rennen wahrscheinlicher. Bisher
gab es genau zwei Stufen: SpoLei durfte alles, der Betreuer durfte **nur** seinen
eigenen Standort senden. Alles andere lief in ein 403 — und weil das Frontend 403
wie 401 behandelte, flog der Betreuer beim ersten Fehltipp aus der Sitzung.

Gleichzeitig stand die **Rennverwaltung** jedem offen, auch nicht angemeldeten
Zuschauern: der Knopf `🏁 Rennen` hatte keinerlei Rechteprüfung. Löschen,
Startlisten, Strecken — alles sichtbar, alles einen Fehlgriff entfernt.

2.5.0 verschiebt die Grenze dorthin, wo sie im Rennbetrieb hingehört:

- **Der Betreuer führt die Taktik** seines Rennens: Gruppen bilden und auflösen,
  Runden zählen, Zeitmessungsvorschläge annehmen oder verwerfen.
- **Das Rennen selbst bleibt beim SpoLei**: anlegen, ändern, starten, beenden,
  löschen, Startlisten, Strecke, Marker, Tracker, Anzeigetexte, Sollrunden.

Möglich wurde das erst durch 2.4.0: seitdem trägt `POST /groups` einen
`race`-Parameter und jedes Gerät wählt sein eigenes Rennen. Vorher wäre jeder
Schreibzugriff eines Betreuers im Leitrennen gelandet.

---

## Was sich für wen ändert

### Betreuer darf jetzt zusätzlich

| Funktion | Endpunkt |
|---|---|
| Gruppen bilden, aufteilen, zusammenführen, benennen, Abstände setzen | `POST /groups` |
| Runden vor- und zurückzählen | `POST /races/:id/lap` |
| Zeitmessungsvorschlag übernehmen | `POST /timing/apply` |
| Zeitmessungsvorschlag verwerfen | `POST /timing/dismiss` |

Alle vier sind rennbezogen — über den `race`-Parameter beziehungsweise die
Renn-ID im Pfad. Ein Betreuer schreibt ausschließlich in das Rennen, das er in
den Rennkacheln gewählt hat.

### Betreuer sieht nicht mehr

- **Die Rennverwaltung.** Der Knopf `🏁 Rennen` verschwindet aus dem Kopf der
  Taktikansicht *und* aus der Kopfzeile — beide Wege. Auch für nicht angemeldete
  Besucher.
- **`⭐ Favoriten`.** Favoriten hängen an der Startliste; die gehört dem SpoLei.

### Unverändert gesperrt

Veranstaltungen und Rennen anlegen/ändern/löschen/aktivieren/beenden, Start,
Sollrundenzahl und `startOffset` (`PATCH /races/:id/laps`), Startlisten, GPX,
Start/Ziel, Marker, Fahrer ergänzen/umbenennen/entfernen, Fahrerstatus,
Favoriten, Tracker umbenennen/zuordnen/löschen, Karte leeren, Anzeigetexte,
Renn-Modus, Team-Auto-Position, Zeitmessung einrichten, `DELETE /groups`.

### Unverändert erlaubt

Karte und Positionen ansehen, eigenen Standort teilen, Protokoll-CSV, Abstände,
Zeitmessungsstand lesen, Kartenansicht-Einstellungen, **Rennkacheln** (die sind
die Rennauswahl, nicht die Rennverwaltung).

---

## Nebenwirkung, die eigentlich eine Fehlerbehebung ist

`checkAuth()` behandelte 401 und 403 gleich und meldete bei beiden ab. Mit zwei
Rollen sind das zwei verschiedene Lagen:

| Status | Bedeutung | ab 2.5.0 |
|---|---|---|
| 401 | Token gilt nicht mehr (z. B. Render-Cold-Start) | abmelden, Anmeldefenster |
| 403 | angemeldet, aber nicht befugt | Sitzung bleibt, kurzer Hinweis |

Ohne diese Trennung hätte ein Betreuer sich beim ersten Tipp auf einen
SpoLei-Knopf selbst abgemeldet — mitten im Rennen.

### 11. `core/auth.js` — `checkAuth()` trennt 401 und 403

**ALT**
```js
// Rueckgabe: true = Antwort ist brauchbar, false = Sitzung ist hin.
let authWarned = false;

function checkAuth(res) {
  if (!res || (res.status !== 401 && res.status !== 403)) return true;
  // Nicht angemeldet zu sein ist kein Sitzungsabbruch.
  if (!authToken) return false;
  authToken = null;
```

**NEU**
```js
// Ab 2.5.0 werden 401 und 403 getrennt behandelt. Mit zwei Rollen sind
// das zwei verschiedene Lagen:
//   401 = der Token gilt nicht mehr  -> abmelden, neu anmelden lassen
//   403 = angemeldet, aber nicht befugt -> Sitzung bleibt, nur Hinweis
// Bis 2.4.1 loeste beides eine Abmeldung aus. Ein Betreuer, der einmal
// auf einen SpoLei-Knopf tippt, flog damit mitten im Rennen aus der
// Sitzung - genau der Fehlgriff, gegen den diese Version gebaut ist.
//
// Rueckgabe: true = Antwort ist brauchbar, false = Aufruf ist gescheitert.
let authWarned = false;
let rechtWarned = false;

function checkAuth(res) {
  if (!res || (res.status !== 401 && res.status !== 403)) return true;
  // Nicht angemeldet zu sein ist kein Sitzungsabbruch.
  if (!authToken) return false;
  if (res.status === 403) {
    if (!rechtWarned) {
      rechtWarned = true;
      if (typeof showToast === 'function') {
        showToast('\u{1F512} Daf\u00FCr fehlt die Berechtigung');
      }
      setTimeout(() => { rechtWarned = false; }, 3000);
    }
    return false;
  }
  authToken = null;
```

## Breaking Changes

Keine. Bestehende SpoLei-Sitzungen und -Abläufe bleiben unverändert; für den
Betreuer kommen Rechte hinzu und die Rennverwaltung fällt weg. Keine Änderung an
Datenbank, Tokens, Umgebungsvariablen oder API-Verträgen. Ein Client der
Version 2.4.1 funktioniert gegen einen 2.5.0-Server weiter — er zeigt dem
Betreuer nur noch den Rennen-Knopf, dessen Aktionen der Server abweist.

---

## Rollback

`updates/2.5.0.md` löschen und die sieben geänderten Dateien aus dem Stand
2.4.1 zurückspielen; `version.json` auf `2.4.1` setzen. Kein Datenbank- oder
Datenrückbau nötig, da nichts persistiert wurde. Der Service Worker zieht den
alten Cache-Namen automatisch aus `version.json`.

**Nach dem Deploy prüfen:** In Render muss `BETREUER_PASSWORD` gesetzt sein.
Fehlt die Variable, greift der Code-Rückfall `betreuer123` — und der öffnet
jetzt mehr als vorher.
