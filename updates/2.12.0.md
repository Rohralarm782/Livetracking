# 2.12.0 — Hauptfeld nach Import

**Datum:** 05.09.2026
**Basis:** `main.zip` MD5 `0f8a8f2c46f50bef67ce4499c9556844`, abgerufen 05.09.2026 16:02 UTC (Repo-Stand 2.11.0)
**Bilanz:** +101 / −5 Zeilen, 5 geänderte Dateien + 1 neue, 7 Hunks

---

## Zweck

Nach einer Übernahme aus der Zeitmessung steht der Hauptfeld-Marker oft an der
falschen Gruppe.

`applyVorschlag()` in `server.js` ordnet die neuen Gruppen **positionsweise**
auf den Bestand:

```js
main: bestand ? bestand.main === true : (i === st.gruppen.length - 1)
```

Der Marker hängt damit am Index, nicht an der Gruppe. Kommen aus der
Zeitmessung mehr Gruppen als vorher — drei Ausreißergruppen statt einer —,
rutscht das Hauptfeld nach vorn und die Gruppe, in der tatsächlich das Feld
fährt, gilt als Gruppetto. Das ist kein Schönheitsfehler: `buildDisplayText()`
beendet den Garmin-Text am Hauptfeld, ein falsch stehender Marker schneidet also
die Ausgabe im Auto an der falschen Stelle ab.

Ab 2.12.0 rechnet die Oberfläche nach jedem Import nach und **fragt**. Umgesetzt
wird nichts von allein — die größte Gruppe ist im Rennen meistens, aber nicht
immer das Hauptfeld; im Gruppetto laufen mehrere Gruppen zusammen, ohne dass
deshalb das Feld dort wäre.

## Wie es sich zeigt

Kein neuer Knopf, kein Balken, kein Dialog: der ohnehin vorhandene **graue
HF-Knopf** der größten Gruppe färbt sich orange und heißt `HF?`. Ein Tipp
darauf läuft in das vorhandene `setMainGroup()` — mit allem, was daran hängt:
automatische Benennung, Speichern, Rückgängig als „↶ Hauptfeld". Wer ihn
ignoriert, hat nichts weiter zu tun.

Dazu kommt der Hinweis in der Meldung nach dem Übernehmen:

```
vorher:  ⏱ Übernommen
neu:     ⏱ Übernommen · größte Gruppe: Gruppetto (24)
```

Der Zusatz erscheint nur, wenn es einen Vorschlag gibt.

## Regeln

1. **Auslöser ist allein der Import.** Der Vorschlag entsteht in
   `timingApply()`, also beim Übernehmen eines Zeitmessungsstandes — auch beim
   Übernehmen einer einzelnen Gruppe. Beim Verschieben von Fahrern von Hand
   entsteht keiner: wer selbst umsortiert, weiß, wo das Feld ist.
2. **DSQ und DNF zählen nicht mit**, wie überall sonst seit 2.10.0. `/timing/apply`
   gibt die Fahrer allerdings als reine Nummern zurück — `sanitizeGroups()`
   streift den Zustand ab, angereichert wird erst der nächste Poll. Der Zustand
   kommt deshalb aus dem Stand **vor** dem Import, gesammelt in `hfZustaende()`.
   Kein zusätzlicher Aufruf zum Server.
3. **Mindestvorsprung zwei Fahrer** (`HF_VORSPRUNG = 2`). 12 gegen 11 ist kein
   Grund, das Hauptfeld zu verschieben.
4. **Kein Vorschlag ohne eindeutiges Größtes.** Sind zwei Gruppen gleich groß,
   schweigt die Anzeige.
5. **Welche Gruppe als Hauptfeld gilt**, wird wie in `mainGroupIdx()` und im
   Server bestimmt: ausdrücklicher `main`-Marker, sonst die letzte Gruppe.
6. **Der Vorschlag steht bis zum nächsten Import** oder bis der HF-Marker
   gesetzt wird. Beim Zeichnen wird zusätzlich geprüft, ob die Gruppe *noch* die
   größte ist: wandern zwischendurch Fahrer, verschwindet die Färbung still,
   statt auf eine überholte Lage zu zeigen. Beim Wechsel des Arbeitsrennens wird
   er verworfen (`arbeitsRennenNachladen()`), weil die Gruppen-ID dort nicht
   existiert.
7. **Auch für Betreuer.** Die Bedingung ist `authToken`, dieselbe wie beim
   grauen HF-Knopf; das Setzen selbst erlaubt `POST /groups` dem Betreuer seit
   2.5.0. Ohne Anmeldung gibt es weder Knopf noch Vorschlag.

## Bewusst nicht geändert

- **`server.js` bleibt unberührt.** Die naheliegende Stelle wäre
  `applyVorschlag()` — dort das Hauptfeld automatisch auf die größte Gruppe zu
  setzen. Das widerspräche der Grundregel „die Zeitmessung überschreibt nichts
  von allein" und wäre im Gruppetto regelmäßig falsch.
- **`aktivZahl()` in `race/taktik-ui.js`** bleibt, wie es ist. Die neue
  Funktion `hfZahl()` in `race/timing.js` rechnet dasselbe, kann aber zusätzlich
  mit reinen Nummern und einer Zustandstabelle umgehen — genau der Fall
  unmittelbar nach dem Import. Für den Tooltip am Knopf wird weiterhin
  `aktivZahl()` benutzt, dort liegen die angereicherten Daten vor.
- **`race/favorites.js`** unberührt.

**NEU** — derselbe Abschnittskopf bleibt stehen, davor kommt ein neuer Block:

```js
// ---------------------------------------------------------------------
// Hauptfeld-Vorschlag nach einem Import
// ---------------------------------------------------------------------
// applyVorschlag() im Server ordnet die neuen Gruppen positionsweise auf
// den Bestand: der HF-Marker bleibt am Index haengen, nicht an der
// Gruppe. Kommen aus der Zeitmessung mehr oder weniger Gruppen als
// vorher, steht er danach an der falschen Stelle - und auf dem Garmin
// endet der Text am HF, der Fehler wirkt also bis ins Auto durch.
//
// Umgesetzt wird nichts von allein; das waere gegen die Grundregel der
// Zeitmessung und im Gruppetto oft auch falsch. Stattdessen faerbt sich
// der ohnehin vorhandene graue HF-Knopf der groessten Gruppe.
const HF_VORSPRUNG = 2;        // Mindestabstand in Fahrern, sonst kein Vorschlag
let   hfVorschlagGid = null;   // Gruppe, deren HF-Knopf gerade faerbt

function hfVorschlagLoeschen() { hfVorschlagGid = null; }

// Gruppengroesse ohne DSQ/DNF - wie aktivZahl() in race/taktik-ui.js.
// Eigene Fassung, weil /timing/apply die Fahrer als reine Nummern
// zurueckgibt (sanitizeGroups streift den Zustand ab). Der Zustand kommt
// dann aus dem Stand vor dem Import, uebergeben in "zust".
function hfZahl(g, zust) {
  return ((g && g.riders) || []).filter(r => {
    const nr = (r && r.nr !== undefined) ? r.nr : r;
    const st = (r && r.status) || (zust ? zust[nr] : null);
    return !(st === 'dsq' || st === 'dnf');
  }).length;
}

// Zustaende aus dem Stand vor dem Import, nach Startnummer.
function hfZustaende(gruppen) {
  const zust = {};
  (gruppen || []).forEach(g => ((g && g.riders) || []).forEach(r => {
    if (r && r.nr !== undefined && r.status) zust[r.nr] = r.status;
  }));
  return zust;
}

// Liefert { gid, name, zahl } oder null. Kein Vorschlag, wenn:
//   - weniger als zwei Gruppen da sind
//   - zwei Gruppen gleich gross sind (kein eindeutiges Groesstes)
//   - die groesste Gruppe schon das Hauptfeld ist
//   - ihr Vorsprung kleiner als HF_VORSPRUNG ist (12 gegen 11 ist kein Grund)
// Welche Gruppe als Hauptfeld gilt, wird wie in mainGroupIdx() und im
// Server bestimmt: ausdruecklicher main-Marker, sonst die letzte Gruppe.
function hfVorschlagRechne(gruppen, zust) {
  const list = Array.isArray(gruppen) ? gruppen.filter(Boolean) : [];
  if (list.length < 2) return null;
  const zahlen = list.map(g => hfZahl(g, zust));
  let max = -1, maxIdx = -1, doppelt = false;
  zahlen.forEach((z, i) => {
    if (z > max)       { max = z; maxIdx = i; doppelt = false; }
    else if (z === max) doppelt = true;
  });
  if (maxIdx < 0 || doppelt || max <= 0) return null;
  const mIdx = list.findIndex(g => g.main === true);
  const hfIdx = mIdx >= 0 ? mIdx : list.length - 1;
  if (maxIdx === hfIdx) return null;
  if (max - zahlen[hfIdx] < HF_VORSPRUNG) return null;
  return { gid: list[maxIdx].id, name: list[maxIdx].name || 'Gruppe', zahl: max };
}

// Frage der Oberflaeche: faerbt der HF-Knopf dieser Gruppe? Der Vorschlag
// wird dabei jedes Mal neu gerechnet - wandern zwischendurch Fahrer,
// verschwindet er still, statt auf eine ueberholte Lage zu zeigen.
function hfVorschlagFuer(gid) {
  if (!authToken || !hfVorschlagGid || hfVorschlagGid !== gid) return false;
  const v = hfVorschlagRechne(taktikGroups, null);
  return !!(v && v.gid === gid);
}
```

Keine gelöschte Zeile — reiner Zuwachs vor einem unveränderten Abschnittskopf.

## Rollback

Die fünf geänderten Dateien aus dem Stand 2.11.0 zurückspielen; `updates/2.12.0.md`
kann stehen bleiben. Die Änderung ist rein additiv und berührt weder Datenbank

Wert setzen, dann entsteht nie ein Vorschlag.
