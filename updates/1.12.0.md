## Das Problem

Marker sind unterschiedlich alt. Ist der eine 2 s alt und der andere 20 s,
klaffen bei 45 km/h ueber 200 m Phantomabstand, obwohl die beiden
nebeneinander fahren. Schneller senden hilft nur begrenzt: bei 5 s bleiben
immer noch rund 60 m.

Die Loesung ist Zeitgleichheit statt Aktualitaet. Jeder Punkt traegt seinen
Zeitstempel; statt „letzte bekannte Position\" wird „Position aller Fahrer zum
Zeitpunkt T\" gezeigt, T = jetzt minus Rueckstand. Der Preis ist ein Kartenbild,
das der Wirklichkeit um den Rueckstand hinterherhinkt — fuer die taktische
Beurteilung zaehlen die Abstaende zueinander, nicht die absolute Aktualitaet.

Gemessen an einem nachgestellten Fall — zwei Fahrer nebeneinander, letzte
Punkte 2 s und 20 s alt:

| | Abstand |
|---|---|
| Letzte Positionen, wie bisher | **189 m** |
| Auf denselben Zeitpunkt gerechnet | **13 m** |

Ohne Zeitabgleich ist auch keine verlaessliche Gruppierung moeglich: ein
Cluster ueber ungleich alte Marker reisst Zusammengehoerige auseinander und
wirft Getrennte zusammen. Deshalb gehoeren beide Schalter in dasselbe Update.

## Neu in der Bedienung

Unter **Erweiterte Einstellungen** gibt es die neue Gruppe **Kartenansicht**
mit drei Bedienelementen. Beide Schalter sind **standardmaessig aus** — nach
dem Deploy aendert sich zunaechst nichts an der Karte.

- **Zeitabgleich.** An: alle Fahrer werden auf denselben Zeitpunkt gerechnet.
  Aus: jeder Marker zeigt seine letzte Meldung, wie bisher.
- **Rueckstand**, Schieberegler 5–60 s in Fuenferschritten, Vorgabe 25 s.
  Erscheint nur bei eingeschaltetem Zeitabgleich. Bei 20 s Sendeintervall des
  Garmin-Datenfelds sind 25–30 s sinnvoll, bei 5 s reichen 15 s.
- **Gruppen zusammenfassen.** Fahrer im Umkreis von 30 m werden zu einem
  Marker mit der Anzahl zusammengefasst; der Tooltip nennt die Namen. Bei 30 m
  liegen die Einzelmarker auf der Karte ohnehin uebereinander.

Alle drei Einstellungen liegen in `localStorage` (`syncPref`, `syncLagS`,
`groupPref`) und ueberleben einen Neuladen der Seite. Sie sind pro Geraet, es
gibt keine Serverseite dazu.

Teamauto und Betreuer bleiben von beidem ausgenommen: das Teamauto gehoert dem
eigenen Browser, Betreuer stehen fest an der Verpflegungszone.

## Geaenderte Stellen im Einzelnen

### 1 — `server.js`, `projectToTrack()` wird zu `projectToTrackDetail()`

Die Funktion rechnete den Abstand zur Strecke intern immer schon aus
(`bestD`), warf ihn aber weg. Er wird jetzt zurueckgegeben.

**ALT (3 Zeilen)**
```js
function projectToTrack(raceId, lat, lon, hintS) {
  const g = trackGeometry(raceId);
  if (!g) return null;
```

**NEU (12 Zeilen)**
```js
const TRACK_MAX_OFFSET_M = 200;

// Liefert { s, distM } oder null. projectToTrack() bleibt als
// schlanke Huelle daneben stehen, damit die bestehenden Aufrufer
// unveraendert weiterlaufen.
function projectToTrackDetail(raceId, lat, lon, hintS) {
  const g = trackGeometry(raceId);
  if (!g) return null;
```

Am Ende derselben Funktion:

**ALT (2 Zeilen)**
```js
  if (bestS === null && typeof hintS === 'number') return projectToTrack(raceId, lat, lon, undefined);
  return bestS;
```

**NEU (9 Zeilen)**
```js
  if (bestS === null && typeof hintS === 'number') return projectToTrackDetail(raceId, lat, lon, undefined);
  if (bestS === null) return null;
  // bestD ist ein Quadrat in Meter-Einheiten (die Koordinaten wurden
  // oben ueber metersPerDeg skaliert), deshalb hier die Wurzel.
  return { s: bestS, distM: Math.sqrt(bestD) };
}

function projectToTrack(raceId, lat, lon, hintS) {
  const d = projectToTrackDetail(raceId, lat, lon, hintS);
  return d === null ? null : d.s;
}
```

Der Aufrufer in `POST /races/:id/laps` (Start/Ziel aus einer Koordinate) sieht
dadurch keinen Unterschied.

### 2 — `server.js`, `verfolgeStrecke()`

Anlass war ein Befund aus echten Trainingsdaten: `s` stand bei jedem Punkt auf
exakt `9178.655011725168`, obwohl sich `lat` und `lon` bewegten. Weit neben der
Strecke liefert `projectToTrack()` immer den naechstgelegenen Punkt, und der
Suchhinweis haelt die Suche anschliessend dort fest. Zwei Trainingsfahrer in
verschiedenen Stadtteilen haetten dasselbe `s` bekommen und waeren als eine
Gruppe zusammengefasst worden.

**ALT (2 Zeilen)**
```js
  const s    = projectToTrack(activeRaceId, lat, lon, hint);
  if (s === null) return null;
```

**NEU (9 Zeilen)**
```js
  const proj = projectToTrackDetail(activeRaceId, lat, lon, hint);
  if (proj === null) return null;
  const s = proj.s;

  // Weit neben der Strecke ist s bedeutungslos. Die Rundenlogik
  // unten bleibt bewusst unveraendert - sie betrifft nur Tracker im
  // Rennen, und dort waere eine neue Schwelle ein Risiko. Nur der
  // Rueckgabewert, aus dem der Verlauf gespeist wird, faellt weg.
  const brauchbar = proj.distM <= TRACK_MAX_OFFSET_M;
```

Beide `return s;` werden zu `return brauchbar ? s : null;`. Der Aufruf von
`pruefeRundendurchgang(id, s)` ist unveraendert — die Rundenzaehlung verhaelt
sich exakt wie vorher.

### 3 — `map/map.js`, neuer Block vor `loadPositions()`

Reiner Zugang, nichts entfernt. Rund 130 neue Zeilen: `interpoliere()`,
`anzeigePosition()`, `abstandM()`, `bildeGruppen()`, `gruppenIcon()`,
`zeichneGruppen()` sowie die Zustandsvariablen `syncOn`, `groupOn`, `syncLagS`,
`historyData`, `groupMarkers` und die Konstante `GROUP_MAX_M`.

Drei Entwurfsentscheidungen, die im Code kommentiert sind:

- **`interpoliere()` meldet `exakt: false`**, wenn der Zeitpunkt ausserhalb des
  Verlaufs liegt, und liefert dann den Rand. Das passiert bei einem Funkloch
  und wird als Deckkraft 0.65 sichtbar — ein stiller Tracker darf nicht wie ein
  abgehaengter Fahrer aussehen.
- **`s` wird nur interpoliert, wenn kein Rundenschluss dazwischenliegt**
  (`Math.abs(b.s - a.s) < 1000`). Sonst mittelt man zwischen Streckenende und
  Streckenanfang und landet in der Mitte der Runde.
- **`abstandM()` misst entlang der Strecke, wenn beide ein `s` haben**, sonst
  ueber Luftlinie. Zwei Fahrer beidseits einer Haarnadel sind luftlinienmaessig
  50 m auseinander und streckenmaessig 800 m.

### 4 — `map/map.js`, `loadPositions()`

**ALT (2 Zeilen)**
```js
    const res  = await fetch(`${SERVER}/positions`);
    const data = await res.json();
```

**NEU (9 Zeilen)**
```js
    const anfragen = [fetch(`${SERVER}/positions`)];
    if (syncOn) anfragen.push(fetch(`${SERVER}/history?sek=${Math.max(30, syncLagS + 20)}`));
    const [res, hres] = await Promise.all(anfragen);
    const data = await res.json();
    if (hres) {
      try { historyData = await hres.json(); } catch (e) { historyData = {}; }
    } else {
      historyData = {};
    }
```

Der Verlauf wird nur geholt, wenn der Zeitabgleich an ist. Beide Anfragen
laufen parallel, der Sekundentakt bleibt unveraendert.

In der Schleife wird die gezeichnete Position aus `anzeigePosition()` bezogen
statt direkt aus `pos`:

**ALT** `      const latlng      = [pos.lat, pos.lon];`
**NEU** `      const anz         = anzeigePosition(id, pos, zielT, isBetreuer);`
       `      const latlng      = [anz.lat, anz.lon];`

Dadurch folgen Marker, Spuren und Autozoom alle derselben abgeglichenen
Position — sie koennen nicht auseinanderlaufen.

Die Deckkraft bekommt eine dritte Stufe:

**ALT** `        if (!isBetreuer) markers[id].setOpacity(stale ? 0.45 : 1);`
**NEU** `        if (!isBetreuer) markers[id].setOpacity(stale ? 0.45 : (anz.unsicher ? 0.65 : 1));`

`zeichneGruppen(gruppenKandidaten)` laeuft direkt vor dem Autozoom-Block. Beim
Aufraeumen verschwundener Tracker wird zusaetzlich `historyData[id]` geloescht.

## Zusammenspiel mit Stufe 1 (1.11.x)

Dieses Update setzt den Ringpuffer und `GET /history` voraus, die bereits im
Repo stehen. Ohne sie liefert der Zeitabgleich nichts und faellt still auf die
letzte Position zurueck.

Kein Schema, kein Datenformat, keine Migration. Ein Rollback ist ein
Zurueckspielen der fuenf Dateien; die Schalter in `localStorage` bleiben dann
wirkungslos stehen.

## Geprueft

Jeder Patch mit `str.count(old) == 1` erzwungen, vierzehn von vierzehn
eindeutig. `node --check` auf `server.js` und `map/map.js` bestanden,
`version.json` als JSON geparst. Routenbestand 50 → 50 mit identischer Liste.
Funktionsbestand `server.js` +1 (`projectToTrackDetail`), `map/map.js` +7 —
**keine Funktion verloren**. `diff -rq` gegen den Originalstand meldet genau
diese fuenf Dateien, alle uebrigen bytegleich.

Verhaltenstests gegen einen laufenden Server und im jsdom:

- Stapel mit vier Punkten a 5 s → alle vier im Verlauf, mit **eigenen**
  Zeitstempeln. `resolveTimestamp()` behaelt die Geraetezeit, damit traegt die
  Interpolation.
- Phantomabstand 189 m → 13 m nach Abgleich.
- `interpoliere()` mit leerem Verlauf, `null`, Zeitpunkt vor Beginn und nach
  Ende → alle sauber, Randfaelle mit `exakt: false`.
- `bildeGruppen()` ueber Luftlinie: zwei nahe zusammen, einer allein.
- `bildeGruppen()` ueber `s`: greift und ignoriert die Luftlinie korrekt.
- jsdom: alle vier neuen Elemente gefunden, Schalter setzen Klasse, Zustand und
  `localStorage`, der Regler blendet mit dem Zeitabgleich ein und aus, die
  Untertexte wechseln.

## Nicht geprueft

Das Zusammenspiel mit echtem Leaflet liess sich hier nicht nachstellen: das
Ein- und Aushaengen der Marker beim Gruppieren, der Autozoom auf abgeglichene
Positionen und das Verhalten der Spuren beim Umschalten. Beim ersten Einsatz
darauf achten, ob Marker nach dem Aufloesen einer Gruppe zuverlaessig
zurueckkommen.

Der Ausschluss der `g-`-IDs aus der Rundenzaehlung (aus Stufe 1) ist weiterhin
nur statisch geprueft — dafuer braucht es ein aktives Rennen mit GPX.
