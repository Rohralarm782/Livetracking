# v1.15.1 – Kartenschlüssel für Voyager (CARTO)

**Datum:** 28.08.2026
**Typ:** Korrektur / Betrieb
**Basis:** v1.15.0 („Spur kommt vom Server")

## Zweck

CARTO verlangt seit August 2026 einen API-Schlüssel für die Raster-Basemaps.
Anfragen ohne Schlüssel werden weiterhin beantwortet, aber jede Kachel bekommt
ein „API KEY REQUIRED"-Wasserzeichen aufgedruckt. Betroffen ist ausschließlich
der Stil **Voyager**; **OSM** kommt nicht von CARTO und war nie betroffen.

Der Schlüssel liegt jetzt in der Render-Umgebungsvariable `CARTO_KEY` und wird
zur Laufzeit über einen neuen Endpunkt an das Frontend geliefert. Er steht damit
nicht im öffentlichen Repository und lässt sich ohne Deploy austauschen.

Der Schlüssel ist dadurch nicht geheim — jeder Browser sendet ihn bei jeder
Kachelanfrage mit. Der Gewinn liegt allein darin, dass er nicht im Git steht.

## Geänderte Dateien

| Datei | Änderung |
|---|---|
| `server.js` | Neue Konstante `CARTO_KEY` aus `process.env`, neuer Endpunkt `GET /mapconfig` |
| `map/map.js` | Stiltabelle um `braucht_key` ergänzt, neue Funktionen `ladeCartoKey()` und `setzeTileLayer()`, `applyTileStyle()` umgebaut |
| `version.json` | 1.15.0 → 1.15.1 |
| `updates/1.15.1.md` | neu (diese Datei) |

Unberührt: `index.html`, `sw.js`, `core/*`, `race/*` (insbesondere
`race/favorites.js`), `css/*`, `db.js`, `manifest.json`.

## Verhalten

- **Schlüssel bekannt** (aus `localStorage` vom letzten Besuch): Kacheln laden
  sofort, im Hintergrund wird der Wert aufgefrischt. Nur bei Abweichung wird
  die Ebene neu gebaut.
- **Erster Aufruf auf einem Gerät:** Die Kartenfläche bleibt kurz leer, bis der
  Schlüssel da ist. Absicht — sonst holt der Browser gewässerte Kacheln, die er
  anschließend im Cache festhält.
- **Kein Schlüssel gesetzt oder Server nicht erreichbar:** Voyager lädt ohne
  Schlüssel, also mit Wasserzeichen. **Kein automatischer Wechsel auf OSM** —
  der gewählte Stil bleibt der gewählte. In der Browser-Konsole steht eine
  Warnung.
- **OSM:** unverändert, kein Netzaufruf, kein Schlüssel.

## Voraussetzung im Betrieb

Auf Render muss `CARTO_KEY` gesetzt sein (Environment → Add Environment
Variable). Ohne die Variable ist das Update funktionsfähig, zeigt aber weiter
das Wasserzeichen.

## Breaking Changes

Keine. Neuer Endpunkt, keine geänderte oder entfernte Route, keine geänderte
Funktionssignatur. `applyTileStyle(key)` verhält sich für Aufrufer identisch.

## Rollback

`server.js`, `map/map.js` und `version.json` aus v1.15.0 zurückspielen, dann
deployen. Optional im Browser `localStorage.removeItem('cartoKey')` — der Wert
stört v1.15.0 nicht, wird dort aber auch nicht mehr gelesen. Die
Umgebungsvariable kann stehen bleiben.

## Ausblick

Die Raster-Basemaps von CARTO werden ausgemustert; die Vektor-Basemaps sind der
vorgesehene Nachfolger. Dieses Update kauft Zeit, es löst das Thema nicht
dauerhaft. Ein Umstieg auf eine schlüsselfreie Vektorkarte (MapLibre GL) bleibt
als eigenes Vorhaben offen — nichts, was mitten in der Saison eingebaut wird.
