# Livetracking 1.13.0 — Start/Ziel in der Rennvorbereitung, Rennen beenden

Stand vom 24.08.2026, aufgesetzt auf den Repo-Stand
`codeload.github.com/Rohralarm782/Livetracking/zip/refs/heads/main`,
HEAD `3752a72`, abgerufen 17:09 UTC.

Zwei Änderungen an der Bedienung plus ein Fund. Eigenständig deploybar,
rollback-sicher, keine Datenmigration, keine neue Umgebungsvariable.

## Zweck

**A — Start/Ziel gehört zum Rennen, nicht zu den Einstellungen.**
Der Knopf „📐 Start/Ziel setzen" saß im Optionsmenü und wirkte still auf das
gerade aktive Rennen. Beim Vorbereiten eines Wochenendes mit mehreren Rennen
war das nicht zu bedienen: erst aktivieren, Ziel setzen, nächstes aktivieren.
Er sitzt jetzt als 📐 in der Rennzeile der Rennverwaltung, neben Startliste 📂
und Strecke 🗺 — und funktioniert für **jedes** Rennen mit Strecke, unabhängig
davon, ob es aktiv ist.

**B — Ein Rennen lässt sich beenden.**
Bisher konnte man nur *ein anderes* Rennen aktivieren. Nach dem letzten Lauf
des Tages blieb zwangsläufig eins aktiv, mit laufender Rennuhr und laufendem
Garmin-Text. Der Text „aktiv" in der Rennzeile ist jetzt ein Schalter
„aktiv ✕".

## Bedienung

**📐 in der Rennzeile** öffnet ein Panel direkt unter dem Rennen:

| | |
|---|---|
| **km-Feld + ✓ km** | Kilometer ab Anfang der GPX-Datei. Vorbelegt mit dem aktuellen Wert. Enter speichert. Für die Vorbereitung am Rechner. |
| **📍 Hier** | Legt Start/Ziel auf die aktuelle GPS-Position. Für den SpoLei, der am Zielstrich steht. Wie bisher das 📍 in der Rennzeile. |
| **🗺 Auf Karte tippen** | Schließt die Taktikansicht, hebt die Streckenlinie hervor, ein Tipp setzt den Zielstrich. Erscheint **nur beim aktiven Rennen** — auf der Karte liegt genau dessen Linie. Bei allen anderen steht stattdessen ein Hinweis. |

Die Streckenleiste über der Karte (`#streckenBar`) und ihr „Fertig"-Knopf sind
unverändert geblieben, ESC beendet den Modus weiterhin.

**„aktiv ✕"** fragt nach und beendet dann das Rennen. Danach ist kein Rennen
aktiv: Karte ohne Strecke, leere Taktik, Rennuhr aus. Gruppen, Startliste,
Strecke und Start/Ziel bleiben beim Rennen gespeichert — ein erneutes
Aktivieren stellt alles wieder her (live geprüft, siehe unten).

## Fund neben dem Auftrag

`race/events-ui.js` rief den Startschuss mit vertauschten Argumenten auf:

```js
await apiSend('POST', `/races/${id}/start`, { actual: an });   // falsch
```

`apiSend(path, method, body)` erwartet den Pfad zuerst. `fetch()` bekam
dadurch `method: '/races/…/start'` und warf einen `TypeError` — **der Knopf
„🏁 Start" war seit 1.12.0 wirkungslos.** Die Fahrtzeit lief danach weiter
gegen die geplante Startzeit statt gegen den echten Startschuss.

Das war nicht Teil des Auftrags. Ich habe es mitgenommen, weil es ein
Ein-Zeilen-Tausch ist und ein totes Rennelement bis zum nächsten Update
stehenzulassen schlechter wäre. **Der Hunk ist einzeln herausnehmbar**
(`race/events-ui.js`, Hunk 20) — wenn du ihn getrennt willst, sag Bescheid.

## Breaking Changes

Keine.

- Der Endpoint `PATCH /races/:id/laps` ist unverändert; er konnte schon immer
  auf nicht aktive Rennen wirken.
- `POST /races/:id/deactivate` ist neu und additiv.
- `raceView()` liefert ein zusätzliches Feld `startOffset`. Ältere Clients
  ignorieren es.
- Die HTML-ID `streckenBtn` entfällt. Sie wurde nur von `core/auth.js` und
  `core/ui.js` benutzt, beide sind in dieser Lieferung mit angepasst.
  Ein Deploy nur von `index.html` **ohne** die beiden JS-Dateien würde einen
  `TypeError` beim Login werfen — die drei Dateien gehören zusammen hoch.

## Rollback

Vollständig durch Zurücklegen der neun Dateien aus dem vorherigen Stand.
Es wird nichts geschrieben, was ein alter Stand nicht lesen könnte:

- `startOffset` lag schon vorher in `raceMeta` und im settings-Eintrag
  `raceMeta`, es kommt kein neues Feld in die Datenbank.
- Ein durch „aktiv ✕" beendetes Rennen hat den Status `beendet` und
  `activeRaceId = null` — ein Zustand, den auch der alte Stand kennt
  (er entsteht dort beim Löschen des aktiven Rennens).
- Nach einem Rollback ist schlicht kein Rennen aktiv; über „Aktiv" in der
  Rennzeile ist der alte Zustand in einem Klick wiederhergestellt.

// derselben Rechnung wie eine GPS-Meldung.
async function onTrackClick(e) {
  // Auf der Karte liegt die Strecke des AKTIVEN Rennens. Ein Tipp darf
  // deshalb nie auf ein anderes Rennen gehen, auch wenn zielRaceId aus
  // irgendeinem Grund noch auf einem alten Wert steht.
  if (!streckenModus || !activeInfo || !activeInfo.raceId) return;
  if (zielRaceId && zielRaceId !== activeInfo.raceId) return;
  L.DomEvent.stop(e);
  await sendeZiel({ atLat: e.latlng.lat, atLon: e.latlng.lng }, activeInfo.raceId);
}

// Setzt Start/Ziel eines Rennens. raceId ist optional: ohne Angabe gilt
// das Rennen des Streckenmodus, sonst das aktive. Fehler landen im Toast
// und nicht als Ausnahme beim Aufrufer - der Kartentipp hat keinen
// Platz fuer einen Dialog.
async function sendeZiel(felder, raceId) {
  const ziel = raceId || zielRaceId || (activeInfo && activeInfo.raceId);
  if (!ziel) { showToast('\u26A0\uFE0F Kein Rennen gew\u00E4hlt'); return null; }
  try {
    const d = await setRaceLaps(ziel, felder);
    // Marker und Karte nur anfassen, wenn es wirklich das Rennen ist,
    // das gerade auf der Karte liegt.
    if (activeInfo && ziel === activeInfo.raceId) {
      activeInfo.startOffset = d.startOffset;
      drawFinishMarker();
    }
    if (streckenModus) zeigeZielKm();
    showToast(`\u{1F3C1} Start/Ziel bei km ${(d.startOffset / 1000).toFixed(2).replace('.', ',')}`);
    return d;
  } catch (err) { showToast('\u26A0\uFE0F ' + err.message); return null; }
}
