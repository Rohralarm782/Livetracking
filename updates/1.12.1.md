# Livetracking 1.12.1 – Fehlerbehebung zu 1.12.0

Stand vom 24.08.2026, aufgesetzt auf den ausgelieferten Stand 1.12.0.

Patch-Ausgabe: behebt zwei Fehler aus 1.12.0, keine neuen Funktionen. Wer
1.12.0 noch nicht deployt hat, laedt einfach beide Staende zusammen hoch.

## Was in 1.12.0 kaputt war

Nach dem Deploy von 1.12.0 waren die neuen Schalter tot, der Rueckstand-Regler
ohne Wirkung, und es erschienen **keine Marker mehr auf der Karte**. Der
dritte Punkt war der schwerwiegende: die Karte war damit unbenutzbar.

Alle drei Symptome hatten dieselbe Ursache.

### Fehler 1 — Zustandsvariablen in der zeitlichen Totzone

`updateSyncUi()` und die drei Klick-Behandler standen in `map/map.js` bei
Zeile 326, direkt vor dem bestehenden `autoZoomBtn`-Handler. Die zugehoerigen
Deklarationen `let syncOn / groupOn / syncLagS` lagen dagegen erst bei Zeile
336, im neuen Block vor `loadPositions()`.

Mit `let` deklarierte Variablen sind vor ihrer Deklaration nicht zugreifbar.
Der Aufruf von `updateSyncUi()` warf deshalb einen `ReferenceError`, und die
Datei brach an dieser Stelle ab.

Die Folgen reichten weit ueber die neuen Bedienelemente hinaus: **alles nach
Zeile 326 wurde nie ausgefuehrt.** Auch die bestehenden Behandler fuer
`autoZoomBtn`, `resetBtn`, das Bestaetigungsfenster und das Rechtsklick-Menue
der Marker bekamen keine Registrierung mehr. `loadPositions()` existierte zwar
(Funktionsdeklarationen werden hochgezogen), warf aber beim Zugriff auf
`syncOn` im Sekundentakt denselben Fehler — daher die fehlenden Marker.

**Behebung:** Der Zustandsblock wandert zu den uebrigen Modulvariablen, direkt
hinter `let autoZoom = true;`. Die Hilfsfunktionen bleiben, wo sie waren —
Funktionsdeklarationen werden hochgezogen, `let` nicht.

**ALT** (bei den Hilfsfunktionen, Zeile ~336)
```js
let syncOn   = localStorage.getItem('syncPref')  === 'on';
let groupOn  = localStorage.getItem('groupPref') === 'on';
let syncLagS = (() => { … })();

const GROUP_MAX_M = 30;
let historyData = {};
const groupMarkers = {};
```

**NEU** (bei den Modulvariablen, Zeile ~66)
```js
let autoZoom     = true;

// Zeitabgleich und Gruppen. Muss hier oben stehen, nicht erst bei den
// Hilfsfunktionen weiter unten: die Bedienelemente werden schon beim
// autoZoomBtn verdrahtet, und mit let deklarierte Variablen sind vor
// ihrer Deklaration nicht zugreifbar - die Datei braeche dort ab.
let syncOn   = localStorage.getItem('syncPref')  === 'on';
let groupOn  = localStorage.getItem('groupPref') === 'on';
let syncLagS = (() => { … })();

const GROUP_MAX_M = 30;
let historyData = {};
const groupMarkers = {};
```

### Fehler 2 — `.hidden` wirkt in dieser CSS-Datei nicht generisch

`#syncLagRow` bekam in 1.12.0 die Klasse `hidden`, blieb aber immer sichtbar.
Grund: in `css/app.css` gibt es **keine** generische `.hidden`-Regel. Jede ist
an eine ID gebunden — `#optionsMenu.hidden`, `#raceClock.hidden`,
`#streckenBar.hidden` und so weiter. Eine blosse Klasse traf also auf nichts,
und `.adv-row { display: flex }` blieb wirksam.

**Behebung:** Regel nach der im Repo etablierten Konvention ergaenzt.

**NEU** (nach `#syncLagRange`)
```css
    /* In dieser Datei gibt es keine generische .hidden-Regel - jedes
       .hidden ist an eine ID gebunden. Ohne diese Zeile bliebe der
       Regler immer sichtbar, weil .adv-row auf display:flex steht. */
    #syncLagRow.hidden { display: none; }
```

## Geprueft

Beide Patches mit `str.count(old) == 1` erzwungen. `node --check` auf
`map/map.js` bestanden, `version.json` als JSON geparst.

Neu in der Prueflliste und der eigentliche Grund, warum die Fehler in 1.12.0
durchgerutscht sind: ein **Ladetest der kompletten Datei** in einer
DOM-Umgebung, mit Stubs fuer Leaflet und `fetch`. `node --check` prueft nur die
Syntax — eine zeitliche Totzone ist syntaktisch einwandfrei. Der jsdom-Test zu
1.12.0 hatte lediglich den herausgeschnittenen Verdrahtungsblock geprueft und
konnte den Fehler deshalb gar nicht sehen.

Ergebnis nach der Behebung:

- Laden von `map/map.js` ohne Fehler
- `loadPositions`, `clearMap`, `showMarkerMenu`, `updateSyncUi`,
  `zeichneGruppen` alle definiert
- `autoZoomBtn` wieder klickbar, ohne Ausnahme
- Regler anfangs versteckt, erscheint beim Einschalten des Zeitabgleichs
- Schalter und Regler setzen Klasse, Zustand und `localStorage` korrekt

Regressionsabgleich gegen den Repo-Stand `3594ac3`, also gegen den Zustand vor
1.12.0:

| Pruefung | Ergebnis |
|---|---|
| Routen `server.js` | 50 → 50, identische Liste |
| Funktionen `server.js` | nur `projectToTrackDetail` neu |
| Funktionen `map/map.js` | 7 Zugaenge, **keine entfernt** |
| Event-Listener `map/map.js` | 3 Zugaenge, **keiner verschwunden** |
| Element-IDs `index.html` | 7 Zugaenge, keine entfernt |
| CSS-Selektoren | 3 Zugaenge |
| uebrige Dateien | bytegleich |

Es ist in 1.12.0 nichts verlorengegangen — die Funktionen waren nur
unerreichbar, solange die Datei abbrach.

## Nicht geprueft

Unveraendert offen aus 1.12.0: das Zusammenspiel mit echtem Leaflet. Das Ein-
und Aushaengen der Marker beim Gruppieren, der Autozoom auf abgeglichene
Positionen und das Verhalten der Spuren beim Umschalten liessen sich hier
nicht nachstellen. Beim ersten Einsatz darauf achten, ob Marker nach dem
Aufloesen einer Gruppe zuverlaessig zurueckkommen.

Ebenfalls offen: der Ausschluss der `g-`-IDs aus der Rundenzaehlung (aus
Stufe 1) ist weiterhin nur statisch geprueft — dafuer braucht es ein aktives
Rennen mit GPX.
