# Livetracking 2.6.2 — Strecken im Wechselstrich

**Datum:** 02.09.2026
**Typ:** Korrektur der Darstellung aus 2.6.1 (nur Frontend)
**Basis:** v2.6.1 („Strecken als Fahrspuren")
**Repo-Stand:** `codeload.github.com/Rohralarm782/Livetracking/zip/refs/heads/main`,
abgerufen **02.09.2026, 19:27 UTC** (`map/gpx.js` MD5 `fde55eb7…`, identisch
mit der Lieferung 2.6.1)

Zwei geänderte Dateien plus dieses Protokoll. **+79 / −123 Zeilen** — die
Lieferung ist kleiner als ihre Vorgängerin, weil der Versatzapparat komplett
entfällt. Keine Serveränderung, keine neue Route, keine neue Abhängigkeit.

---

## Zweck

Der Parallelversatz aus 2.6.1 hat auf echten Aufzeichnungen ausgefranste
Linien erzeugt. Ursache: die Versatzrichtung wurde aus je zwei
aufeinanderfolgenden Streckenpunkten bestimmt. Auf einer aufgezeichneten Spur
liegen die Punkte wenige Meter auseinander und tragen GPS-Rauschen, also
schwankt diese Richtung erheblich:

| Punktabstand | Rauschen quer | Schwankung der Richtung |
|---|---|---|
| 30 m | 3 m | ±5° |
| 10 m | 3 m | ±13° |
| 3 m | 3 m | ±35° |

Jeder Punkt wurde damit in eine etwas andere Richtung geschoben; die
Verlängerung an Ecken (`1/cos`) machte aus jedem Rauschknick zusätzlich eine
Spitze. Der jsdom-Test von 2.6.1 lief auf glatten Rechteck- und
Diagonalstrecken und konnte das nicht sehen — das war eine Lücke im Test,
nicht im Zufall.

Ein Nachbessern (Richtung aus einem größeren Fenster glätten) wäre möglich
gewesen, hätte aber einen zweiten zoomabhängigen Parameter gebracht. Statt
dessen der Weg, der gar nichts verschiebt.

## Was neu ist

**Alle Strecken liegen wieder exakt auf der Straße und tragen dasselbe
Strichmuster mit verschobener Phase.** Auf einem gemeinsamen Abschnitt
wechseln sich die Rennfarben ab; jede kommt garantiert vor, unabhängig von der
Straßenrichtung.

- **Strichlänge 18 px**, Muster bei drei Rennen `18 36`, Phasen 0 / 18 / 36.
  Bei zwei Rennen `18 18`. Die Folge wiederholt sich bei drei Rennen alle
  54 px.
- **Dünne durchgezogene Grundlinie** in der Rennfarbe unter den Strichen
  (weight 2, Deckkraft 0.45). Ein Abschnitt, auf dem nur ein Rennen fährt,
  wirkt damit nicht zerrissen.
- **Das eigene Rennen** beginnt bei Phase 0, wird zuletzt gezeichnet und ist
  stärker (weight 7 statt 6).
- **Eine einzelne sichtbare Strecke bleibt durchgezogen**, ebenso der
  Streckenmodus. Gestrichelt wird nur, wenn es etwas zu unterscheiden gibt.
- Das Muster ist ein Bildschirmmaß und macht jeden Zoom unverändert mit. Die
  Neuberechnung bei `zoomend` aus 2.6.1 entfällt ersatzlos — damit auch ihre
  rund 60 ms je Zoomwechsel.

## Was dadurch wieder heil ist

- **Die Geometrie ist unangetastet.** `L.polyline` bekommt `gpxByRace[id]`
  direkt, kein umgerechnetes Punktfeld. Der Kartentipp im Streckenmodus, die
  Kilometrierung und die Lage von Zielflagge, Wertungen und Zonen stimmen
  wieder auf den Meter. Die harte Regel „im Streckenmodus kein Versatz" aus
  2.6.1 wird nicht mehr gebraucht, weil es keinen Versatz mehr gibt.
- **Zonen und Marker passen wieder zur Linie.** In 2.6.1 lag die Zone auf der
  Fahrbahn und die Streckenlinie bis zu 10 px daneben.

## Was ausdrücklich nicht passiert

- `startOffset` und `pruefeRundendurchgang` sind nicht angefasst;
  `server.js` ist byte-identisch.
- `race/favorites.js` ist nicht angefasst.
- Der Klick-Handler hängt weiter an der farbigen Linie. Ist sie gestrichelt,
  trifft ein Tipp genaugenommen nur die Striche, nicht die Lücken — im
  Streckenmodus, wo das zählt, ist die Linie durchgezogen.
- Die Karte läuft im SVG-Renderer (`L.map('map')` ohne `preferCanvas`).
  Nur dort wirkt `dashOffset`; im Canvas-Renderer würde die Phase ignoriert
  und alle Striche lägen deckungsgleich. Falls jemals auf Canvas umgestellt
  wird, ist das die Stelle, die nachzuziehen ist.

// Punkte einer Strecke um px Bildschirmpixel senkrecht zur
// Fahrtrichtung verschieben. Gerechnet wird im Pixelraum der Karte und
// danach zurueck nach Grad; deshalb muss das Ergebnis bei jedem
// Zoomwechsel neu gebildet werden (siehe aktualisiereVersatz).
//
// An einer Ecke zaehlt die Winkelhalbierende beider angrenzenden
// Segmente, verlaengert um 1/cos - sonst schnuerte die Linie in der
// Kurve ein. Bei einer Kehre liefe der Faktor gegen unendlich, deshalb
// ist er bei 0.55 gedeckelt: die Spitze wird dort leicht abgeflacht
// statt quer ueber die Karte zu schiessen.
//
// gpxByRace bleibt unberuehrt. Der Versatz existiert nur in den
// gezeichneten Punkten - Kilometrierung, Marker und Zielstrich rechnen
// weiter mit der echten Strecke.
function versetzteCoords(coords, px) {
  const c = coords || [];
  if (!px || c.length < 2) return c;
  const p = c.map(q => map.latLngToLayerPoint(L.latLng(q[0], q[1])));
  const n = p.length;
  const norm = [];
  for (let i = 0; i < n - 1; i++) {
    const dx = p[i + 1].x - p[i].x, dy = p[i + 1].y - p[i].y;
    const len = Math.sqrt(dx * dx + dy * dy) || 1;
    norm.push([-dy / len, dx / len]);
  }
  const out = [];
  for (let i = 0; i < n; i++) {
    const a = norm[i === 0 ? 0 : i - 1];
    const b = norm[i === n - 1 ? n - 2 : i];
    let nx = a[0] + b[0], ny = a[1] + b[1];
    const len = Math.sqrt(nx * nx + ny * ny) || 1;
    nx /= len; ny /= len;
    const cos = Math.max(0.55, a[0] * nx + a[1] * ny);
    const ll = map.layerPointToLatLng(
      L.point(p[i].x + nx * px / cos, p[i].y + ny * px / cos));
    out.push([ll.lat, ll.lng]);
  }
  return out;
}
