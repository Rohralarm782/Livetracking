**Datum:** 31.08.2026

## Zweck

Beim Zeitfahren steht der Zeitnehmer an einem festen Punkt der Strecke. Wo
genau, wusste bisher nur, wer bei der Streckenbesichtigung dabei war. Ab
1.18.0 lässt sich dieser Ort als Streckenpunkt eintragen und erscheint auf der
Karte — für SpoLei und Betreuer gleichermaßen sichtbar.

Der neue Typ heißt in der Bedienung **ZZ**, intern `zwischenzeit`.

## Was das Update ausdrücklich NICHT tut

**Es misst nichts.** Der Punkt ist eine Markierung, mehr nicht. Eine
automatische Durchfahrtserfassung wäre technisch möglich — `verfolgeStrecke()`
rechnet für jeden Fix ein `s`, `trackerS[id]` hält den Vorgängerwert — sie
setzt aber voraus, dass jeder Fahrer einen Tracker trägt. Solange das nicht der
Fall ist, wäre eine Zwischenzeittabelle mit drei von vierzig Startern
irreführender als gar keine. Deshalb bewusst nur Stufe 1.

Ebenfalls nicht enthalten: eine Kennzeichnung des Rennens als Zeitfahren,
Startzeiten je Fahrer und eine Startreihenfolge-Übersicht. Das ist ein eigenes
Feature mit eigenem Datenmodell und wird getrennt geplant.

## Entscheidungen

| Frage | Entscheidung |
|---|---|
| Beschriftung | **ZZ** (kurz genug für die Typenleiste und die Listenzeile) |
| Punkt oder Zone | **Punkt.** Der Typ steht nicht in `MARKER_ZONE`, ein mitgeschicktes `sEnde` wird verworfen |
| `runden` | läuft unverändert mit — beim Rundenzeitfahren nützlich, beim Einzelstart leer zu lassen |
| Anzeigetext (Garmin) | **nicht enthalten.** `pushAutoDisplays()` und `buildAutoText()` bleiben unberührt |

## Warum der Typ am Ende der Liste steht

`mkArt()` in `race/events-ui.js` fällt für unbekannte Typen auf **`MK_ARTEN[4]`**
zurück — ein hart kodierter Index, der auf „Frei" zeigt. Ein Einschub weiter
oben hätte diesen Rückfall verschoben und jeden unbekannten Marker als
Zwischenzeit angezeigt. Der neue Eintrag steht deshalb an Position 5, und der
Kommentar im Code hält das fest. In `map/gpx.js` ist der Rückfall namensbasiert
(`MARKER_ART.frei`) und damit von der Reihenfolge unabhängig.

Aus demselben Grund wurde `MARKER_TYPEN` in `server.js` angehängt statt
einsortiert.

## Bedienung

Rennverwaltung → Rennen aufklappen → **Punkte auf der Strecke** → **＋ Punkt**
→ **⏱️ ZZ**. Verortung wie bei jedem anderen Streckenpunkt auf drei Wegen:

1. Kilometer eintippen
2. 📍 aktuelle GPS-Position übernehmen — der Weg für die Streckenbesichtigung
3. 🗺 auf Karte tippen (nur beim aktiven Rennen)

Der Punkt erscheint auf der Karte als Stoppuhr im blaugrünen Ring (`#00838f`,
bewusst von allen fünf bestehenden Farben unterscheidbar). Tooltip:
`⏱️ ZZ · km 4,20` bzw. der eingetragene Name.

Die Typenleiste hat jetzt sechs Knöpfe statt fünf. `.mk-typen` trägt bereits
`flex-wrap: wrap`, der sechste bricht sauber um — **`css/app.css` bleibt
unberührt.**

## Breaking Changes

Keine.

- Bestehende Marker sind unangetastet, kein Migrationsschritt.
- Der Deckel bleibt bei 20 Punkten je Rennen (`MARKER_MAX`).
- `POST /races/:id/marker` nimmt einen Typ mehr an und lehnt alles Übrige
  weiterhin mit 400 ab. Die Fehlermeldung listet den neuen Typ mit auf.
- Anzahl der Express-Routen unverändert 59, keine Funktion umbenannt,
  hinzugefügt oder entfernt.

## Rollback

Rückspielen der vier Dateien aus 1.17.0. Bereits eingetragene
Zwischenzeit-Punkte bleiben in `raceMeta[raceId].marker` stehen und werden von
der alten Fassung als unbekannter Typ behandelt: auf der Karte erscheinen sie
über den namensbasierten Rückfall als lila „Punkt", in der Rennverwaltung als
„Frei". Sie lassen sich dort löschen. Ein Bearbeiten und Speichern schlägt mit
400 fehl, weil der alte Server den Typ nicht kennt — dann löschen und neu
anlegen.

Kein Datenverlust, kein Neustart nötig.

# Änderungen im Einzelnen

## `server.js` — +6 / −1

### Hunk 1 — sechster Markertyp

**ALT**
```js
// und braeuchte eine Migration - fuer ein Wort auf einem Knopf.
const MARKER_TYPEN    = ['start', 'wertung', 'berg', 'verpflegung', 'frei'];
```
**NEU**
```js
// und braeuchte eine Migration - fuer ein Wort auf einem Knopf.
// 'zwischenzeit' (Bedienung: "ZZ") kam mit 1.18.0 dazu und markiert
// beim Zeitfahren den Standort des Zeitnehmers. Bewusst NUR eine
// Markierung: gemessen wird hier nichts, dafuer muesste jeder Fahrer
// einen Tracker haben. Deshalb steht der Typ am ENDE der Liste - der
// Rueckfall in events-ui.js zeigt auf einen festen Index.
const MARKER_TYPEN    = ['start', 'wertung', 'berg', 'verpflegung', 'frei', 'zwischenzeit'];
```

`MARKER_ZONE`, `MARKER_MAX` und `MARKER_NAME_MAX` in den Zeilen darunter
bleiben unverändert. Da `zwischenzeit` nicht in `MARKER_ZONE` steht, greift im
Endpoint der bestehende `else`-Zweig und entfernt ein mitgeschicktes `sEnde`
(`delete e.sEnde`) — genau wie bei Sprint und Berg.

## `map/gpx.js` — +2 / −1

### Hunk 2 — Darstellung auf der Karte

**ALT**
```js
  frei:        { icon: '\u{1F4CC}', label: 'Punkt',        farbe: '#6a1b9a', zone: true  }
};
```
**NEU**
```js
  frei:        { icon: '\u{1F4CC}', label: 'Punkt',        farbe: '#6a1b9a', zone: true  },
  zwischenzeit:{ icon: '\u23F1\uFE0F', label: 'ZZ',         farbe: '#00838f', zone: false }
};
```

`markerArt()`, `markerBeschriftung()`, `markerIcon()` und `drawRaceMarker()`
bleiben unverändert — sie lesen die Tabelle und brauchen für einen weiteren
Eintrag keine Anpassung.

## `race/events-ui.js` — +5 / −1

### Hunk 3 — Eintrag in der Bedienung

**ALT**
```js
  { typ: 'frei',        icon: '\u{1F4CC}', label: 'Frei',        zone: true  }
];
```
**NEU**
```js
  { typ: 'frei',        icon: '\u{1F4CC}', label: 'Frei',        zone: true  },
  // Ans Ende, nicht dazwischen: mkArt() faellt unten auf MK_ARTEN[4]
  // zurueck. Ein Einschub weiter oben wuerde jeden unbekannten Typ als
  // Zwischenzeit anzeigen.
  { typ: 'zwischenzeit', icon: '\u23F1\uFE0F', label: 'ZZ',       zone: false }
];
```

`mkArt()`, `markerBlockHtml()`, `mkMeter()` und die Fälle `mk-neu`, `mk-typ`,
`mk-edit`, `mk-save`, `mk-hier`, `mk-karte`, `mk-del` bleiben unverändert. Das
Endefeld erscheint über `mkArt(mkForm.typ).zone` und entfällt damit für den
neuen Typ von selbst.

# Deploy

Vier Dateien plus dieses Protokoll über das lokale Repo entpacken, pushen,
Render deployt.

**Erfolgskontrolle:**

1. Nach dem Deploy einmal hart neu laden — App schließen und öffnen bzw.
   Strg+Shift+R. Der Service Worker legt unter `livetracking-1.18.0` neu an.
2. Rennverwaltung → ein Rennen mit hinterlegter Strecke aufklappen →
   **＋ Punkt**: die Typenleiste zeigt jetzt sechs Knöpfe, der letzte ist
   **⏱️ ZZ**.
3. ZZ wählen: das Feld „Ende km" verschwindet, das Rundenfeld bleibt.
4. Kilometer eintragen und speichern — die Zeile erscheint als
   `⏱️ ZZ · km …`.
5. Rennen aktivieren: der Punkt liegt als blaugrüne Stoppuhr auf der Karte.

Die Startzeile nennt die neue Version:

```
🚀 Tracking Server läuft – v1.18.0 – DB: … – Veranstaltungen: … – Rennen: … – aktiv: …
```
